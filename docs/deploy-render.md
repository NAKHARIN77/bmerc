# เอา BMERC ขึ้นเว็บจริงบน Render

สิ่งที่จะได้: เว็บ 1 ตัว (หน้าเว็บกับ API อยู่ในเครื่องเดียวกัน) และฐานข้อมูล PostgreSQL 1 ตัว ที่ Singapore ซึ่งใกล้ไทยที่สุด
ที่อยู่เว็บจะเป็นแบบ `https://bmerc-xxxx.onrender.com` มี https ให้ฟรี

## ข้อจำกัดของแผนฟรี (สำคัญ)
- **ฐานข้อมูลฟรีหมดอายุใน 30 วัน** แล้วจะถูกลบภายใน 14 วันถัดไป และไม่มี backup ให้
  ก่อนให้ลูกค้าจริงใช้ ต้องอัปเกรดเป็นแบบเสียเงิน (Basic-256mb ราว 6 USD/เดือน)
- **เว็บจะหลับเมื่อไม่มีคนใช้ 15 นาที** ครั้งแรกที่เปิดหลังจากหลับจะรอประมาณ 1 นาที ถ้าอัปเกรดเป็น Starter (7 USD/เดือน) จะไม่หลับ
- เหมาะกับการเดโมและให้ลูกค้ารายแรกลองใช้

## ขั้นตอน

### 1. สมัคร Render แล้วเชื่อมกับ GitHub
1. เข้า render.com → **Get Started** → สมัครด้วย **GitHub** (บัญชี NAKHARIN77)
2. ตอนขอสิทธิ์ ให้เลือก repo **bmerc**

### 2. สร้างจาก Blueprint
1. ใน Render กด **New +** → **Blueprint**
2. เลือก repo **bmerc** แล้ว Render จะอ่านไฟล์ `render.yaml` เอง จะเห็นรายการ `bmerc` (web) และ `bmerc-db` (database)
3. ช่อง `SMTP_URL` กับ `MAIL_FROM` ปล่อยว่างไว้ก่อนได้ (ใส่ตอนตั้งอีเมลเสร็จ)
4. กด **Apply** แล้วรอประมาณ 5–10 นาที ครั้งแรกต้อง build นาน

### 3. คัดลอกข้อมูลตัวอย่างขึ้นไป
1. ใน Render เปิด **bmerc-db** → **Connect** → **External** → คัดลอก **External Database URL**
2. เปิดไฟล์ `apps/api/.env` ในเครื่อง แล้วเพิ่มบรรทัดนี้ (**อย่าส่ง URL นี้ในแชท** เพราะมีรหัสผ่านอยู่ในนั้น):
   ```
   RENDER_DATABASE_URL=postgresql://...ที่คัดลอกมา...
   ```
3. บอก Claude ว่า **"ใส่ URL แล้ว"** แล้ว Claude จะรันคำสั่งนี้ให้:
   ```
   PG_CONTAINER=bmerc-db-1 npm run db:copy-to -- --yes
   ```
   คำสั่งนี้สำรองข้อมูลในเครื่องก่อน แล้วค่อย**แทนที่**ข้อมูลบน Render ทั้งหมด ส่วนเว็บที่รันอยู่ใช้ต่อได้เลย ไม่ต้องรีสตาร์ท

### 4. ลองใช้
- เปิด `https://<ชื่อ>.onrender.com` → Log in ด้วยบัญชีตัวอย่าง เช่น `admin@siamhash.demo`
- จุดตรวจสุขภาพของเว็บอยู่ที่ `https://<ชื่อ>.onrender.com/api/v1/health` (ใช้กับ UptimeRobot ดู [operations.md](operations.md))

## เกิดอะไรขึ้นตอนเว็บเริ่มทำงาน
`deploy/start.sh` ทำงานตามลำดับนี้ทุกครั้ง:
1. `prisma migrate deploy`: อัปเดตโครงสร้างฐานข้อมูลถ้ามีเวอร์ชันใหม่ ข้อมูลเดิมยังอยู่ครบ
2. `scripts/prepare-db.mjs`: สร้างผู้ใช้ฐานข้อมูล `bmerc_app` ที่ถูกระบบ RLS คุม ให้ API ใช้ตัวนี้ ถ้า Render ไม่ให้สร้าง API จะใช้ผู้ใช้เจ้าของแทน ซึ่งก็ยังปลอดภัย เพราะตารางของบริษัทเปิด FORCE RLS ไว้หมด และ log จะบอกว่าใช้แบบไหน
3. เปิด API ที่ 127.0.0.1:4000 (ภายในเท่านั้น) และเปิดหน้าเว็บที่ `$PORT`

## อัปเดตเว็บทีหลัง
รวมงานเข้า `main` บน GitHub แล้ว Render จะ build และอัปเดตเว็บให้เอง (Auto-Deploy)

## ก่อนเปิดขายจริง
- [ ] ย้ายฐานข้อมูลไปที่ที่ไม่หมดอายุ (Neon ฟรี) หรืออัปเกรด Render
- [ ] ใส่ข้อมูลจริงใน `apps/web/src/lib/legal.ts` (ชื่อบริษัทที่จดทะเบียน ที่อยู่ อีเมลติดต่อ) และให้นักกฎหมายตรวจหน้า `/privacy` กับ `/terms`
- [ ] **ลบข้อมูลตัวอย่าง + สร้างบัญชีเจ้าของระบบจริง** ด้วยคำสั่งเดียว:
  1. ใส่ใน `apps/api/.env`: `OWNER_EMAIL=...`, `OWNER_NAME=...`, `OWNER_PASSWORD=...` (12 ตัวขึ้นไป)
  2. รัน `PG_CONTAINER=bmerc-db-1 node apps/api/scripts/go-live.mjs --yes`
     ระบบจะสำรองข้อมูลไว้ที่ `backups/before-go-live/` ก่อน แล้วลบบริษัท ผู้ใช้ งาน และ log ทั้งหมด
     แต่เก็บแพ็กเกจ รายการรุ่นเครื่อง และประวัติ migration ไว้ แล้วสร้างบัญชีเจ้าของระบบใหม่ ถ้าพลาดตรงไหนจะไม่มีอะไรถูกลบ
  3. ล็อกอินด้วยบัญชีใหม่ แล้วลบ `OWNER_PASSWORD` ออกจาก `.env`
- [ ] ใส่ `SMTP_URL` และ `MAIL_FROM` ใน Render → bmerc → Environment
- [ ] ตั้ง UptimeRobot และใส่โดเมนจริง (Render → Settings → Custom Domains)
